### Fixed
- **Stale file rows after an Audiobookshelf re-import** (#1692) — moving books to a different folder or library in ABS and re-importing added a row for the new path but kept the old, dead one, so a book's file path could point at a file that no longer existed. A library scan never cleaned it up either, because it skips any book that still resolves at least one file. The ABS importer now prunes a book's other rows for the same format when their files are genuinely gone, and `DELETE /api/v1/book/{id}/file?path=…` deregisters a single tracked path without touching the disk, for instances that already accumulated dead rows. Rows are only pruned when the file is confirmed missing, so an unmounted share does not clear a library.
