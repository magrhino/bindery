### Fixed
- **Books holding both an ebook and an audiobook now declare themselves as dual-format.** `media_type` records what Bindery was told to acquire, but the Book detail page renders files through it, so a book carrying an epub alongside an audiobook while declaring only one of them badged the wrong format, downloaded the wrong file, and offered a delete dialog that named one path while the handler removed both. `refreshBookStatus` now widens `media_type` to `both` whenever `book_files` holds both formats. This is inventory-driven and deliberately independent of the metadata-driven widening pinned in #1732 — that pin guards Hardcover hydration, where the audiobook is only a claim; here the file is already on disk. Affected books heal on the next file event (import, delete, rename, or library reorganize); no migration runs at upgrade.
- **The legacy `file_path` column now prefers the path matching the book's media type** instead of always taking the ebook. That column is what the format-less download endpoint and OPDS serve, so an audiobook whose `file_path` pointed at a stray ebook handed out the wrong file.
- **`?mediaType=both` now filters the book list instead of being ignored.** The `ebook` and `audiobook` filters deliberately include dual-format books, so neither one isolated them and the `both` value fell through the switch and returned the whole library. The Books page gained a matching **📖🎧 Both** filter button.
