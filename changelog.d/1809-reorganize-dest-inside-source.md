### Fixed
- **Reorganize no longer hangs (and fills the disk) when a book's destination lands inside its own folder** (#1809) — a layout change that computes a destination underneath the source folder (a flat `Author/` directory becoming `Author/Title/`, or a series folder named after the book) could not be done with a rename, so the copy-based folder move took over and recursed into the directory it had just created, copying the book into itself until the drive filled or the operation was killed. Reorganize now flags such a file as an error in the preview ("destination would be inside the source folder") and leaves it alone, and the directory move/copy primitives refuse a destination nested inside the source outright instead of walking into it.
