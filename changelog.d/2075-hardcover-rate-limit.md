### Fixed
- **Hardcover requests are now paced and retried instead of storming a rate limit** (#2075) — the Hardcover client sent one request and returned whatever came back, so a burst of parallel lookups had most of them refused: a single 72-item Audiobookshelf import produced 86 `HTTP 429: API rate limit exceeded for tier 'Free'` rejections across four call sites, and the "Try again in 1 seconds" the response itself carried was never read. Requests now pace themselves adaptively and a refused request is retried, honouring Hardcover's own retry hint (`Retry-After` when sent, the message text otherwise). The pacing costs nothing until Hardcover actually refuses something, hardens if it keeps refusing, and relaxes again after a run of successful requests, so a paid-tier token is never slowed down for a limit it does not have. A rejected request is also now classifiable as a rate limit rather than only as a generic failure, which is what lets callers stop treating it as "this record does not exist".
